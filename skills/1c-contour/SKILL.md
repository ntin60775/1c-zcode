# Контур 1С под ZCode: инварианты и маршрутизация

## Инварианты

1. **Исходники 1С правятся только через Unica MCP** (`mcp__unica__*`).
   Прямая правка `edit`/`write`/`sed -i`/перенаправлениями блокируется гейтом
   `unica-source-gate`. Чтение (`read`, `grep`, `glob`) — свободно.
   Разовая прямая правка, которую Unica не выражает (например, комментарий
   вне тела метода), — через `.zcode/unica-gate-escalations.txt` в корне
   дерева: одна строка = путь относительно корня; после правки строку убрать.
2. **Расширение грузится всегда полной пересборкой** (`fullRebuild: true`),
   **основная конфигурация — никогда**: частичная загрузка расширений падает
   на формах, полная пересборка main — десятки минут. Пока это проза:
   исполняемого гейта инварианта в ZCode-порте ещё нет.
3. Все вызовы Unica обязаны нести `cwd` корня проекта (или ворктри, если
   работа идёт там): без него workspace резолвится в каталог плагина.

## Маршрутизация: файл → инструмент Unica

| Файл / тип | Инструмент |
|---|---|
| `*.bsl` (модуль) | `unica.code.patch` |
| `Form.xml` | `unica.form.edit` / `unica.form.compile` |
| `Configuration.xml` | `unica.cf.edit` |
| XML метаданных (справочник, документ, регистр…) | `unica.meta.edit` / `unica.meta.add` |
| `Role.xml` / `Rights.xml` | `unica.role.edit` / `unica.role.compile` |
| СКД `Template.xml` | `unica.dcs.edit` / `unica.dcs.compile` |
| MXL `Template.xml` | `unica.mxl.compile` / `unica.mxl.decompile` |
| `Subsystem.xml` | `unica.subsystem.edit` / `unica.subsystem.compile` |
| `CommandInterface.xml` | `unica.interface.edit` |
| XDTO `*.xsd` | `unica.xdto.edit` |
| Заимствование в расширение | `unica.cfe.borrow` |

## Что ещё не перенесено из omp-контура

Скелет: исполняем только гейт исходников. Замок на инфобазу (одна серверная
база на все деревья), сверка перед записью, дисциплина ретраев, гейт
изменяющих инструментов MCP_Сервер и playbook'и тестового контура — проза
донора, перенос по мере надобности. До переноса соответствующие инварианты
соблюдать вручную.
