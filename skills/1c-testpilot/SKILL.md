# 1c-testpilot: карта тест-клиента для агента

Апстрим-дока — `docs/TOOLS.md` репо 1c-testpilot (все 160 операций) и `docs/PYTHON_TESTING.md`
(Python API). Здесь — то, что реально нужно агенту, плюс ловушки, оплаченные
на живом стенде и в апстрим-доке отсутствующие.

## Два режима подключения

| Режим | Когда | Как |
|---|---|---|
| `launch_client` | обычный GUI-e2e: клиент поднимается сам в приватном Xvfb | `Client(profile=...)` в with-блоке; профиль с `base` |
| **attach** | клиент УЖЕ открыт (на дисплее владельца, чужой стенд) | `Client(host="127.0.0.1", port=N)` или `connect(port=N)` |

- Тест-клиент слушает TCP только при старте с ключами `/TESTCLIENT
  -TPort<N>` — ДВА отдельных аргумента, без кавычек (формат из
  `_runtime.py`: `'-TPort' + str(port)`; кавычки вокруг значения ломают
  ключ). Обычный клиент владельца без этих ключей не подключить.
- **Запуск тест-клиента — только раннером** (`Client(profile=...)`,
  `launch_client`): раннер сам выбирает exe платформы, для isolated
  поднимает приватный Xvfb и ждёт готовности порта. Голый ручной
  `1cv8c ENTERPRISE … /TESTCLIENT …` умирает мгновенно и тихо (факт
  29.10) — не трать на него время. Ручной запуск имеет смысл только
  как редко нужный attach-цель: на видимый дисплей владельца (адрес из
  `contour.json → 1c.display.visible`, типовой `:1`; нет ключа —
  спроси), с фиксированным портом:
  `env -u WAYLAND_DISPLAY DISPLAY=<видимый> 1cv8c ENTERPRISE
  /IBConnectionString … /TESTCLIENT -TPort48010
  /DisableStartupMessages`, затем `connect(port=48010)`.
- Порт тест-клиента раннер подбирает свободный сам (`free_port()`) —
  параллельные тест-клиенты на разных базах не конфликтуют (проверено
  29.10 двумя одновременными прогонами на двух файловых базах).
  Фиксированный `-TPort<N>` — только для attach-цели.
- `close()` после attach — только disconnect, ЧУЖОЙ клиент не гасит.
  После launch — гасит штатно (15 с, потом kill).
- Клиент тестирования и MCP-клиент 1c-db — **два разных клиента одной
  базы**; на файловой базе одновременно живёт только один процесс: второй
  сеанс навечно висит на «Загрузка конфигурационной информации». Перед
  GUI-тестом гаси 1c-db (`start_1c_db.sh --stop`), после — поднимай обратно.
  Планируй это в фикстуре модуля (паттерн `solo_base`).

## Навигация: открываем существующее, не создаём

**`e1cib/data/<Тип>/<guid>` молча открывает форму НОВОГО пустого объекта**
(«создание») с тем же `form_name` — readback по имени формы ловушки не видит.
Канон открытия существующего:

```python
testpilot.execute_command(command="e1cib/list/Документ.АСМ_АктОтвесаБух")
список = testpilot.find_object(cls="ManagedForm", timeout=30)
строка = список.find_object(cls="FormTable").call(
    "goto_row", column="Номер", value="П-31.07.26/33")
строка.call("choose_row")
карточка = testpilot.find_object(cls="ManagedForm", timeout=30)
```

Критерий успеха — **заголовок окна** (номер + дата в заголовке) и поля формы,
НЕ `form_name`: у списка и карточки одного типа он может совпадать частично,
а ловушка `e1cib/data` даёт тот же `form_name`, что и настоящая карточка.

`execute_command` принимает только `e1cib/...`-ссылки — имена кнопок и
«человеческие» команды не работают. Кнопки нажимай по элементу формы
(`кнопка.click()`), контекстное меню приходит как отдельная форма-группа
(`get_child_objects`).

## Readback-критерии (что считается доказательством)

- Форма открыта и та: заголовок окна + контрольные реквизиты.
- Кнопка нажата: `is_enabled`/`is_visible` ДО нажатия (возвращают dict —
  распаковывай), после — наблюдаемая реакция: новое окно / сообщение формы
  (`get_user_message_texts()` — требует открытой панели сообщений; надёжнее
  окно/реквизит) / изменение реквизита.
- Окно закрыто: элемент исчез из `get_child_objects` (не «нажал и надеюсь»).
- Форма заполнена правильно: readback ключевых полей (сумма, основание,
  назначение) после открытия.

## Модальность и динамические списки

- `find_object(cls="ManagedForm")` видит только АКТИВНОЕ окно — перед
  поиском убедись, что нужное окно сверху (`activate`/`close_window`).
- `get_context` может падать, пока динамический список (десятки тысяч строк)
  обновляется — оборачивай в retry с коротким таймаутом (3–5 попыток).
- Результат прерванного действия может быть `outcome_unknown`;
  `cleanup_pending=true` — соединение ещё освобождается, дождись
  `busy=false` перед следующим вызовом.

## Реестр операций: «действие в 1С → как сделать через тест-клиент»

Пополняемый реестр рецептов. Это единственное место, где живут проверенные
способы базовых действий; при написании любого GUI-теста **сначала смотри
сюда**, потом TOOLS.md апстрима (полный справочник сигнатур —
`docs/TOOLS.md` репо 1c-testpilot).

**Как пополнять (обязанность агента, работающего с тест-клиентом):**
нашёл новый способ сделать базовое действие — добавь строку в реестр
(коммитом в репо 1c-zcode, скилл `1c-testpilot`) и **сразу оформи issue
в репо контура сам** (`gh issue create -R ntin60775/1c-zcode`): заголовок
«[testpilot] <операция> — <суть находки/ловушки>», тело = рецепт +
условия воспроизведения + версия платформы. Любая проблема с тест-клиентом,
с которой столкнулся в сессии, — issue, не «кандидат»: агент оформляет его
сам до конца сессии. Обход без фиксации знаний теряется; найденная ловушка
без issue — незавершённая работа.

### Навигация и окна

| Операция в 1С | Как через тест-клиент | Примечания |
|---|---|---|
| Открыть существующий объект (документ/справочник) | `execute_command("e1cib/list/Документ.X")` → в списке `goto_row(column, value)` → `choose_row()` | **НЕ `e1cib/data/<Тип>/<guid>`**: молча открывает форму НОВОГО пустого объекта с тем же `form_name`. Критерий успеха — заголовок окна, не `form_name` |
| Дождаться нужную форму после execute_command | повторять `find_object(cls="ManagedForm")` до совпадения точного `form_name` | **гонка**: активным окном успевает стать всплывающая «ОбщаяФорма.ДлительнаяОперацияОткрытиеСписка» с тем же заголовком, что у будущего списка — ловите её вместо списка (2026-10-03) |
| Открыть произвольную форму/обработку | `execute_command("e1cib/data/Обработка.X/Форма.Форма")` | для обработок — прямая ссылка формы |
| Открыть список с отбором по ссылке | `execute_command("e1cib/list/Документ.X?ref=<guid>")` | если не сработало — fallback через список + `goto_row` |
| Активировать нужное окно | `get_active_window()` → `activate()`; между окнами `goto_next_window`/`goto_previous_window` | `find_object` видит только активное окно |
| Опознать активное окно | `get_active_window()` — идентификатор окна в поле **`key`** (`HomePage[<guid>]`), поля `ref` у окна НЕТ | оконные операции (`activate`, `close_window`) принимают этот `key` как параметр `ref` — ассерт на `result['ref']` ломается (issue #21); доку чинил апстрим в 1.9.1 («key/class/title», `_WINDOW_FIELDS` знает оба поля), поведение подтверждено на 1.9.1 живьём 2026-10-19 |
| Элемент после открытия/закрытия дочернего окна | переполучить `find_object` заново | прежние Element'ы инвалидируются («The element is no longer available») не только после переподключения, но и после открытия/закрытия окон поверх |
| Закрыть окно с подтверждением readback | `close_window()` → проверить исчезновение из `get_child_objects()`; изменённая форма даёт отказ «окно ещё открыто» → `answer_dialog(confirm=False)` («Данные были изменены. Сохранить изменения?»); модальный вопрос — `answer_dialog` | «нажал и надеюсь» не считается |
| Перейти на стартовую страницу | `execute_command("e1cib/app/НачалоРаботы")` или `goto_start_page` | |

### Формы: чтение и ввод

| Операция в 1С | Как через тест-клиент | Примечания |
|---|---|---|
| Прочитать форму целиком | `form.get_context(result_mode="full")` | **контракт**: без `result_mode` первый вызов возвращает всю форму, повторные — только ИЗМЕНЕНИЯ (пусто, если форма не менялась); `get_context()` может падать при обновлении динамического списка — retry 3–5 раз |
| Прочитать несколько полей | `form.call("read_fields", fields=[...])` или `client.read_fields([элементы])` | дешевле полного контекста |
| Ввести текст в поле | `поле.input_text(text=...)` → readback `get_text()`/`get_data_presentation()` | «ввёл» без readback не считается |
| Отменить ввод в поле | `поле.call("cancel_edit")` — только при НЕЗАВЕРШЁННОМ вводе (`input_text(..., finish=False)`) | после завершённого ввода `cancel_edit` отвечает ok, но значение НЕ откатывает (issue #9; семантика зафиксирована апстримом в доке 1.9.0) — откат: повторный ввод исходного или закрытие без записи |
| Заполнить несколько полей | `form.call("set_fields", ...)` | останавливается при проблеме, возвращает шаги |
| Выбрать значение ссылочного поля | `select_value` (по тексту из списка или колонкам формы выбора); «из списка»: `start_choosing` → окно выбора (`find_objects(cls="Table")` → `goto_first_row` → `read_rows`) → `choose_row` | `start_choosing` возвращает `opened` + `window`; после выбора — readback поля (`get_text`) |
| Выбрать из выпадающего списка | `open_drop_list` → выбор, или сразу `choose_from_drop_list(value=...)` | |
| Флажок | `set_check()` — toggle; readback: `observed.value_before/value_after` в ответе + `get_text()` ('Да'/'Нет') | **`current_check` для поля-флажка НЕ поддержан** («does not support this action for this element type») — он для кнопок-флажков (issue #3) |
| Дата из календаря | `goto_date`, календарные операции `calendar_*` | на поле даты документа 8.3.27 НЕ поддержаны («does not support this action for this element type», issue #4; семантика документирована апстримом в 1.9.0: календарные операции — только для элемента календаря); дату вводить `input_text` + readback |
| Реквизиты доступны/видимы/редактируемы | `is_enabled`/`is_visible`/`is_readonly` — возвращают **dict**, распаковывай | ловушка: кнопка в оверфлоу командной панели отвечает visible/enabled=true, а `click` отказывает «not visible» (issue #5; апстрим в 1.9.0 задокументировал: при отказе раскрытия подменю нажимай непосредственно нужную дочернюю команду, включая вложенные подменю) — критерий «нажал» только наблюдаемая реакция |

### Таблицы (табличные части, списки)

| Операция в 1С | Как через тест-клиент | Примечания |
|---|---|---|
| Найти строку | `таблица.call("find_rows", conditions=[{"column": "<заголовок колонки>", "text": "...", "match": "exact"}])` — match: exact / contains / starts_with / ends_with | conditions — СПИСОК условий, не dict (issue #8); это НЕ поиск по всей базе. 1.9.2 документировал формат: 1–32 условия, все должны выполняться; `column` — точный отображаемый заголовок; `match` по умолчанию `exact`, регистр по умолчанию не важен (`case_sensitive=False`); ошибка Python API подсказывает формат и режимы сравнения |
| Найти по строке поиска списка (БСП) | `таблица.call("search", text="…")` → строки результата; очистка — `text=""` | 1.9.2: строка поиска ВНУТРИ таблицы или её командной панели используется напрямую; вынесенная на форму — локальному клиенту уходит `Ctrl+F` по таблице, текст вводится только после подтверждения фокуса (фокус при этом меняется); открылся штатный диалог «Найти» — закрывается без ввода, отказ `search_dialog_required`; удалённому клиенту доступен только прямой путь к строке внутри таблицы. Живьём НЕ проверено, на предварительную проверку фокуса закладывай время |
| Перейти и выбрать строку | `goto_row(column, value)` → `choose_row()` / `select_row` | `goto_row` сам отчитывается `found` + `value_before/value_after` |
| Перейти к первой строке списка | `goto_first_row` → readback `get_selected_rows` (ровно одна строка) | 1.9.0: раньше первый переход выделял НЕСКОЛЬКО строк (наш #1/апстрим #21); на 1.9.0 проверено живьём 2026-10-05 — выделение одна строка |
| Добавить строку | `table_add_row` или `add_rows` (сразу с значениями) → `set_row_values` → readback `get_cell_text` | |
| Изменить/удалить строку | `change_row`, `delete_row(s)`, пометка удаления — `switch_row_delete_mark` | |
| Скопировать строку | `copy_row` → таблица уходит в режим редактирования строки → `end_edit_row()` подтвердит / `end_edit_row(cancel=True)` откатит | до завершения `read_rows` откажет «row editing»; мутация только в форме — закрывать без записи (2026-10-03) |
| Прочитать строки | `read_rows`, ячейку — `get_cell_text(column="<имя ЭЛЕМЕНТА колонки>", напр. ТоварыНаименование)`; усечение маркировано: `truncated=true` + `row_count=null`, полный подсчёт — `max_rows=0` (контракт 1.9.1) | `read_rows` надёжен на табличных частях; **на динсписках 1.9.1 читает** (проверено живьём 2026-10-16 на списке справочника: строки и колонки читаются, `truncated=false`, `row_count` сходится; обход «НЕ использовать» из эпохи 1.9.0 снят, на ОГРОМНЫХ списках не перепроверено); таблица списка — класс **`Table`** внутри формы (не `FormTable` — тот для табличных частей карточек); глобальный `find_objects(cls="Table")` без окна находит и таблицы чужих форм (напр. виджетов начальной страницы, «The table is hidden») — ищите `find_object` внутри окна списка; `inactive_page` = таблица на неактивной странице: отказ содержит `page` (key+name) → `activate` по ней → повторить; 1.9.2: две колонки с одинаковым именем дают `ambiguous_column` на проверке текущей строки — передавай имя ЭЛЕМЕНТА из `find_objects` |
| Сортировка/отбор списка | `set_order`, `set_list_settings`; доступные поля — `get_list_settings_fields`; readback — `get_list_settings` | настройки списка — пользовательские: после теста сбрасывать `set_list_settings(filters=[], replace=True)` (2026-10-03) |

### Кнопки, команды, сообщения

| Операция в 1С | Как через тест-клиент | Примечания |
|---|---|---|
| Нажать кнопку формы | `кнопка.click()` → реакция: новое окно/сообщение/реквизит | `is_enabled`/`is_visible` ДО нажатия (но они лгут для оверфлоу — см. выше) |
| Открыть форму НОВОГО объекта (без записи) | кнопка «Создать» списка (`ФормаСоздать.click()`) | пустая форма + «Провести и закрыть» = безопасный источник сообщений проверки заполнения: документ не записывается, данные не мутируются (2026-10-03) |
| Провести/записать документ | кнопка формы (`ПровестиИЗакрыть` и т.п.) + readback (заголовок/реквизит/ЖР) | мутация: данные с маркером Е2Е- и очисткой |
| Команда командного интерфейса | 1.9.0 читает ДЕРЕВО: `get_command_interface()` — команды текущего окна; `all_sections=True` — обзор разделов (id в поле `section`, `command_count`, `total_commands`); затем `section=<id>` или `search=` с тем же `all_sections=True` — команды постранично (`limit` 1–200, `offset=next_offset`), у команды `title`/`path`/`url`, запуск — `execute_command(command=url)` | **1.9.1 подтверждено живьём (2026-10-16)**: первый вызов по окну возвращает непустой `commands` (ok=true) — пустого каталога нет; неудачный обзор разделов честно падает `ActionError` с `scan_error` («this is not an empty catalogue») вместо пустого ответа; на окне без кнопок разделов (начальная страница) — `scan_error: sections_unavailable`, скан разделов веди из окна с панелью разделов; обход переключает разделы, возможны `scan_error`/`restoration_error` («окно изменилось, новое окно оставлено открытым»); поиск и листание идут по кэшу обхода; синтаксис id: `section:<uuid>` / `e1cib/command/Подсистема.X` (issue #6 закрыт фиксом 1.9.0, живьём: 20 разделов, 480 команд) |

### Соединение

| Операция в 1С | Как через тест-клиент | Примечания |
|---|---|---|

### Свод правил реестра

1. Каждое действие заканчивается readback-доказательством.
2. Рецепт в реестре > догадка: если способа нет — разведуй, добавь строку,
   предложи issue.
3. Проблема с тест-клиентом в сессии = кандидат на issue в репо контура —
   предлагай оформление сразу, не откладывай.

## Ограничения MCP execute_code (1c-db)

В серверном execute_code недоступны интерактивное `ОткрытьФорму` и
`РасширенияКонфигурации` — это про UI, у 1c-db другой контекст. Разведку
форм делай testpilot'ом, данные — 1c-db.

## Пароли и стенд

- Пароль светится в cmdline клиента (`/IBConnectionString`) — известное
  ограничение; не публиковать, ротация — задача владельца `v8project.local.yaml`.
- Тест-клиент на видимый дисплей: `env -u WAYLAND_DISPLAY
  DISPLAY=<1c.display.visible из contour.json, дефолт :1> …` — адрес
  видимого дисплея машина-специфичен, не хардкодь (софтверный рендер
  `GDK_BACKEND=x11 LIBGL_ALWAYS_SOFTWARE=1` по ситуации);
  в Xvfb — `desktop: isolated` профиля.
