# 1c-testpilot: карта тест-клиента для агента

Апстрим-дока — `docs/TOOLS.md` клона (все 160 операций) и `docs/PYTHON_TESTING.md`
(Python API). Здесь — то, что реально нужно агенту, плюс ловушки, оплаченные
на живом стенде и в апстрим-доке отсутствующие.

## Два режима подключения

| Режим | Когда | Как |
|---|---|---|
| `launch_client` | обычный GUI-e2e: клиент поднимается сам в приватном Xvfb | `Client(profile=...)` в with-блоке; профиль с `base` |
| **attach** | клиент УЖЕ открыт (на дисплее владельца, чужой стенд) | `Client(host="127.0.0.1", port=N)` или `connect(port=N)` |

- Клиент тестирования слушает TCP только при старте с ключом
  `/TESTCLIENT '-TPort'48010` (формат вприлип, из `_runtime.py`). Обычный
  клиент владельца без этого ключа НЕ подключить — сначала поднять
  тест-клиента с TPort (на видимый дисплей: `env -u WAYLAND_DISPLAY
  DISPLAY=:1 1cv8c ENTERPRISE /IBConnectionString … /TESTCLIENT '-TPort'48010
  /DisableStartupMessages`), затем `connect(port=48010)`.
- `close()` после attach — только disconnect, ЧУЖОЙ клиент не гасит.
  После launch — гасит штатно (15 с, потом kill).
- Клиент тестирования и MCP-клиент 1c-db — **два разных клиента одной
  базы**; на файловой базе одновременно живёт только один процесс: второй
  сеанс навечно висит на «Загрузка конфигурационной информации». Перед
  GUI-тестом гаси 1c-db (`start_1c_db.sh --stop`), после — поднимай обратно.
  Планируй это в фикстуре модуля (паттерн `solo_base`).

## Навигация: открываем существующее, не создаём

**`e1cib/data/<Тип>/<guid>` молча открывает форму НОВОГО пустого объекта**
(«создание») с тем же `form_name` — readback по имени формы ловушки не видит.
Канон открытия существующего:

```python
testpilot.execute_command(command="e1cib/list/Документ.АСМ_АктОтвесаБух")
список = testpilot.find_object(cls="ManagedForm", timeout=30)
строка = список.find_object(cls="FormTable").call(
    "goto_row", column="Номер", value="П-31.07.26/33")
строка.call("choose_row")
карточка = testpilot.find_object(cls="ManagedForm", timeout=30)
```

Критерий успеха — **заголовок окна** (номер + дата в заголовке) и поля формы,
НЕ `form_name`: у списка и карточки одного типа он может совпадать частично,
а ловушка `e1cib/data` даёт тот же `form_name`, что и настоящая карточка.

`execute_command` принимает только `e1cib/...`-ссылки — имена кнопок и
«человеческие» команды не работают. Кнопки нажимай по элементу формы
(`кнопка.click()`), контекстное меню приходит как отдельная форма-группа
(`get_child_objects`).

## Readback-критерии (что считается доказательством)

- Форма открыта и та: заголовок окна + контрольные реквизиты.
- Кнопка нажата: `is_enabled`/`is_visible` ДО нажатия (возвращают dict —
  распаковывай), после — наблюдаемая реакция: новое окно / сообщение формы
  (`get_user_message_texts()` — требует открытой панели сообщений; надёжнее
  окно/реквизит) / изменение реквизита.
- Окно закрыто: элемент исчез из `get_child_objects` (не «нажал и надеюсь»).
- Форма заполнена правильно: readback ключевых полей (сумма, основание,
  назначение) после открытия.

## Модальность и динамические списки

- `find_object(cls="ManagedForm")` видит только АКТИВНОЕ окно — перед
  поиском убедись, что нужное окно сверху (`activate`/`close_window`).
- `get_context` может падать, пока динамический список (десятки тысяч строк)
  обновляется — оборачивай в retry с коротким таймаутом (3–5 попыток).
- Результат прерванного действия может быть `outcome_unknown`;
  `cleanup_pending=true` — соединение ещё освобождается, дождись
  `busy=false` перед следующим вызовом.

## Ограничения MCP execute_code (1c-db)

В серверном execute_code недоступны интерактивное `ОткрытьФорму` и
`РасширенияКонфигурации` — это про UI, у 1c-db другой контекст. Разведку
форм делай testpilot'ом, данные — 1c-db.

## Пароли и стенд

- Пароль светится в cmdline клиента (`/IBConnectionString`) — известное
  ограничение; не публиковать, ротация — задача владельца `v8project.local.yaml`.
- Тест-клиент на видимый дисплей: `env -u WAYLAND_DISPLAY DISPLAY=:1 …`
  (софтверный рендер `GDK_BACKEND=x11 LIBGL_ALWAYS_SOFTWARE=1` по ситуации);
  в Xvfb — `desktop: isolated` профиля.
