# 1c-testpilot: карта тест-клиента для агента

Апстрим-дока — `docs/TOOLS.md` клона (все 160 операций) и `docs/PYTHON_TESTING.md`
(Python API). Здесь — то, что реально нужно агенту, плюс ловушки, оплаченные
на живом стенде и в апстрим-доке отсутствующие.

## Два режима подключения

| Режим | Когда | Как |
|---|---|---|
| `launch_client` | обычный GUI-e2e: клиент поднимается сам в приватном Xvfb | `Client(profile=...)` в with-блоке; профиль с `base` |
| **attach** | клиент УЖЕ открыт (на дисплее владельца, чужой стенд) | `Client(host="127.0.0.1", port=N)` или `connect(port=N)` |

- Клиент тестирования слушает TCP только при старте с ключом
  `/TESTCLIENT '-TPort'48010` (формат вприлип, из `_runtime.py`). Обычный
  клиент владельца без этого ключа НЕ подключить — сначала поднять
  тест-клиента с TPort (на видимый дисплей: `env -u WAYLAND_DISPLAY
  DISPLAY=:1 1cv8c ENTERPRISE /IBConnectionString … /TESTCLIENT '-TPort'48010
  /DisableStartupMessages`), затем `connect(port=48010)`.
- `close()` после attach — только disconnect, ЧУЖОЙ клиент не гасит.
  После launch — гасит штатно (15 с, потом kill).
- Клиент тестирования и MCP-клиент 1c-db — **два разных клиента одной
  базы**; на файловой базе одновременно живёт только один процесс: второй
  сеанс навечно висит на «Загрузка конфигурационной информации». Перед
  GUI-тестом гаси 1c-db (`start_1c_db.sh --stop`), после — поднимай обратно.
  Планируй это в фикстуре модуля (паттерн `solo_base`).

## Навигация: открываем существующее, не создаём

**`e1cib/data/<Тип>/<guid>` молча открывает форму НОВОГО пустого объекта**
(«создание») с тем же `form_name` — readback по имени формы ловушки не видит.
Канон открытия существующего:

```python
testpilot.execute_command(command="e1cib/list/Документ.АСМ_АктОтвесаБух")
список = testpilot.find_object(cls="ManagedForm", timeout=30)
строка = список.find_object(cls="FormTable").call(
    "goto_row", column="Номер", value="П-31.07.26/33")
строка.call("choose_row")
карточка = testpilot.find_object(cls="ManagedForm", timeout=30)
```

Критерий успеха — **заголовок окна** (номер + дата в заголовке) и поля формы,
НЕ `form_name`: у списка и карточки одного типа он может совпадать частично,
а ловушка `e1cib/data` даёт тот же `form_name`, что и настоящая карточка.

`execute_command` принимает только `e1cib/...`-ссылки — имена кнопок и
«человеческие» команды не работают. Кнопки нажимай по элементу формы
(`кнопка.click()`), контекстное меню приходит как отдельная форма-группа
(`get_child_objects`).

## Readback-критерии (что считается доказательством)

- Форма открыта и та: заголовок окна + контрольные реквизиты.
- Кнопка нажата: `is_enabled`/`is_visible` ДО нажатия (возвращают dict —
  распаковывай), после — наблюдаемая реакция: новое окно / сообщение формы
  (`get_user_message_texts()` — требует открытой панели сообщений; надёжнее
  окно/реквизит) / изменение реквизита.
- Окно закрыто: элемент исчез из `get_child_objects` (не «нажал и надеюсь»).
- Форма заполнена правильно: readback ключевых полей (сумма, основание,
  назначение) после открытия.

## Модальность и динамические списки

- `find_object(cls="ManagedForm")` видит только АКТИВНОЕ окно — перед
  поиском убедись, что нужное окно сверху (`activate`/`close_window`).
- `get_context` может падать, пока динамический список (десятки тысяч строк)
  обновляется — оборачивай в retry с коротким таймаутом (3–5 попыток).
- Результат прерванного действия может быть `outcome_unknown`;
  `cleanup_pending=true` — соединение ещё освобождается, дождись
  `busy=false` перед следующим вызовом.

## Реестр операций: «действие в 1С → как сделать через тест-клиент»

Пополняемый реестр рецептов. Это единственное место, где живут проверенные
способы базовых действий; при написании любого GUI-теста **сначала смотри
сюда**, потом TOOLS.md апстрима (полный справочник сигнатур —
`contrib/clones/1c-testpilot/docs/TOOLS.md`).

**Как пополнять (обязанность агента, работающего с тест-клиентом):**
нашёл новый способ сделать базовое действие — добавь строку в реестр
(коммитом в репо 1c-zcode, скилл `1c-testpilot`) и **предложи оформить
issue в репо контура** (https://github.com/ntin60775/1c-zcode): заголовок
«[testpilot] <операция> — <суть находки/ловушки>», тело = рецепт +
условия воспроизведения + версия платформы. Любая проблема с тест-клиентом,
с которой столкнулся в сессии, — кандидат на issue: не молчи и не «обходи
молча», обход без фиксации знаний теряется. Найденная ловушка без issue —
незавершённая работа.

### Навигация и окна

| Операция в 1С | Как через тест-клиент | Примечания |
|---|---|---|
| Открыть существующий объект (документ/справочник) | `execute_command("e1cib/list/Документ.X")` → в списке `goto_row(column, value)` → `choose_row()` | **НЕ `e1cib/data/<Тип>/<guid>`**: молча открывает форму НОВОГО пустого объекта с тем же `form_name`. Критерий успеха — заголовок окна, не `form_name` |
| Открыть произвольную форму/обработку | `execute_command("e1cib/data/Обработка.X/Форма.Форма")` | для обработок — прямая ссылка формы |
| Открыть список с отбором по ссылке | `execute_command("e1cib/list/Документ.X?ref=<guid>")` | если не сработало — fallback через список + `goto_row` |
| Активировать нужное окно | `get_active_window()` → `activate()`; между окнами `goto_next_window`/`goto_previous_window` | `find_object` видит только активное окно |
| Закрыть окно с подтверждением readback | `close_window()` → проверить исчезновение из `get_child_objects()`; модальный вопрос — `answer_dialog` | «нажал и надеюсь» не считается |
| Перейти на стартовую страницу | `execute_command("e1cib/app/НачалоРаботы")` или `goto_start_page` | |

### Формы: чтение и ввод

| Операция в 1С | Как через тест-клиент | Примечания |
|---|---|---|
| Прочитать форму целиком | `form.get_context()` | может падать при обновлении динамического списка — retry 3–5 раз |
| Прочитать несколько полей | `form.call("read_fields", fields=[...])` | дешевле полного контекста |
| Ввести текст в поле | `поле.input_text(text=...)` → readback `get_text()`/`get_data_presentation()` | «ввёл» без readback не считается |
| Заполнить несколько полей | `form.call("set_fields", ...)` | останавливается при проблеме, возвращает шаги |
| Выбрать значение ссылочного поля | `select_value` (по тексту из списка или колонкам формы выбора); для «из списка» — `start_choosing` → окно выбора → `choose_row` | после выбора — readback поля |
| Выбрать из выпадающего списка | `open_drop_list` → выбор, или сразу `choose_from_drop_list(value=...)` | |
| Флажок | `set_check(...)` → readback `current_check` | |
| Дата из календаря | `goto_date`, календарные операции `calendar_*` | |
| Реквизиты доступны/видимы/редактируемы | `is_enabled`/`is_visible`/`is_readonly` — возвращают **dict**, распаковывай | |

### Таблицы (табличные части, списки)

| Операция в 1С | Как через тест-клиент | Примечания |
|---|---|---|
| Найти строку | `таблица.call("find_rows", ...)` — по тексту колонок с учётом отборов | это НЕ поиск по всей базе |
| Перейти и выбрать строку | `goto_row(column, value)` → `choose_row()` / `select_row` | |
| Добавить строку | `table_add_row` или `add_rows` (сразу с значениями) → `set_row_values` → readback `get_cell_text` | |
| Изменить/удалить строку | `change_row`, `delete_row(s)`, пометка удаления — `switch_row_delete_mark` | |
| Скопировать строку | `copy_row` | в конце сессии не забудь погасить созданную копию |
| Прочитать строки | `read_rows`, ячейку — `get_cell_text` | `inactive_page` = таблица на неактивной странице — сначала `get_current_page`/переключись |
| Сортировка/отбор списка | `set_order`, `set_list_settings`; доступные поля — `get_list_settings_fields` | |

### Кнопки, команды, сообщения

| Операция в 1С | Как через тест-клиент | Примечания |
|---|---|---|
| Нажать кнопку формы | `кнопка.click()` → реакция: новое окно/сообщение/реквизит | `is_enabled`/`is_visible` ДО нажатия |
| Провести/записать документ | кнопка формы (`ПровестиИЗакрыть` и т.п.) + readback (заголовок/реквизит/ЖР) | мутация: данные с маркером Е2Е- и очисткой |
| Команда командного интерфейса | `get_command_interface` → `click` по команде | |
| Сообщения пользователю | `get_user_message_texts()` | требует открытой панели сообщений; надёжнее окно/реквизит |
| Диалоги (вопросы, предупреждения) | `answer_dialog`, `find_default_button` | |
| Экспорт/печать в файл | `write_content_to_file`, `set_file_dialog_result` | |

### Скриншоты и статусы

| Операция в 1С | Как через тест-клиент | Примечания |
|---|---|---|
| Скриншот окна | `get_screenshot()` (PNG + метаданные) | на дисплее владельца import/скриншоты вне клиента не видят формы 1С — только это |
| Проверить заголовок | `title_is_shown` | надёжный критерий «та ли форма» |
| Сравнить состояние формы | `create_snapshot` → `compare_snapshot` | снимки в памяти до stop |
| Статус выполнения | `get_max_action_time`/`set_max_action_time`, `busy`/`cleanup_pending` | дождись `busy=false` |

### Соединение

| Операция в 1С | Как через тест-клиент | Примечания |
|---|---|---|
| Обычный GUI-e2e | `Client(profile=...)` (with-блок) — сам поднимет и погасит | профиль с `base`, `desktop: isolated` |
| Присоединиться к живому клиенту | поднять клиента с `/TESTCLIENT '-TPort'N` (вприлип) → `Client(host="127.0.0.1", port=N)` | `close()` после attach = только disconnect |
| Список соединений/профилей | `list_connections`, `list_profiles` | |
| Гасить клиента | `stop_client` (после launch) | после attach чужой клиент не гасим |

### Свод правил реестра

1. Каждое действие заканчивается readback-доказательством.
2. Рецепт в реестре > догадка: если способа нет — разведуй, добавь строку,
   предложи issue.
3. Проблема с тест-клиентом в сессии = кандидат на issue в репо контура —
   предлагай оформление сразу, не откладывай.

## Ограничения MCP execute_code (1c-db)

В серверном execute_code недоступны интерактивное `ОткрытьФорму` и
`РасширенияКонфигурации` — это про UI, у 1c-db другой контекст. Разведку
форм делай testpilot'ом, данные — 1c-db.

## Пароли и стенд

- Пароль светится в cmdline клиента (`/IBConnectionString`) — известное
  ограничение; не публиковать, ротация — задача владельца `v8project.local.yaml`.
- Тест-клиент на видимый дисплей: `env -u WAYLAND_DISPLAY DISPLAY=:1 …`
  (софтверный рендер `GDK_BACKEND=x11 LIBGL_ALWAYS_SOFTWARE=1` по ситуации);
  в Xvfb — `desktop: isolated` профиля.
