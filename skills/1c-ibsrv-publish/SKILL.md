# Публикация 1С-базы: ibsrv на Linux (без Apache и root)

## Границы с unica

`unica.run` (адаптер v8-runner) покрывает push/pull/apply/make/upload/download,
dt-дамп и запуск клиентов — **публикации в его поверхности нет** (документный
gap 0.13; ibcmd публиковать тоже не умеет — только `server config init` для
скелета конфига). Поэтому: правки и сборка — unica, публикация — этот скилл.
Штатный путь контура — `publish_ib.sh start|stop|status [путь-к-базе]`:
он сам генерирует конфиг публикации из `contour.json` и сам закрывает грабли
из этого скилла. Руками `build/.ibsrv/ibases.json` не править — `start`
затирает; менять настройки в `contour.json → 1c.publish`.

## Модель

`ibsrv` — автономный сервер (платформа 8.3.21+, тот же комплект, что `ibcmd`):
работает от обычного пользователя, без Apache, root и vrd; веб-клиент,
Конфигуратор, тонкий клиент и тесты живут в одном uid — исчезают конфликты
прав на журналы блокировок, которые давал Apache. Слушает только `127.0.0.1`.
Конфиг — файл с YAML-синтаксисом и расширением `.json` (парсится нормально,
не ловушка). Скелет вручную: `ibcmd server config init` — даёт каркас **без**
секции `http` и **без** настоящего UUID базы, обе вещи дописывать.

## Настройки публикации (что генерирует publish_ib.sh из contour.json)

- `server.address: 127.0.0.1` + `server.port` — порт из `1c.publish.port`;
  разные проекты на машине — разные порты.
- `database.path` — абсолютный путь к файловой базе.
- `infobase.id` — **только настоящий UUID базы**: источник — `DoNotCopy.txt`
  в каталоге базы (его пишет дистрибутив конфигурации). Случайный UUID
  оставляет зомби — сервер жив, HTTP не биндит, в логе тихо.
- `infobase.schedule-jobs: deny` — регламентные задания выключены.
- `http: [{base: /, http-services: {service: [{name, root, publish: true,
  extension-name?}]}}]` — список включённых HTTP-сервисов. **Базовая
  публикация (`base: /`) сама по себе сервисы не публикует** — без блока
  все `/hs/*` отдают 404.

`1c.publish.http_services` в contour.json: `["ИмяСервиса"]` или
`[{"name", "root", "extension"}]` (алиас ключа `extension-name`).

## HTTP-сервисы

- Адресация — `/hs/<root>/<шаблон>`; пробы мимо `/hs/` бессмысленны
  (unmatched GET всегда 404, POST всегда 405).
- Сервис расширения публикуется записью с `extension-name` (имя расширения
  в ИБ); без него платформа сервис расширения не видит. По умолчанию
  расширения **не** публикуются — в отличие от Apache-публикации с
  `publishExtensionsByDefault`. Массовый `publish-extensions-by-default`
  не включать: в расширении может лежать опасный сервис (например,
  удалённое выполнение кода) — точечная публикация безопаснее.
- Basic-авторизацию из конфига не задать: логин/пароль пользователя ИБ
  передаёт сам клиент. Анонимный доступ — только через реверс-прокси,
  подставляющий учётку.

## Диагностика по кодам (проверено живым сервером)

| Код | Значение |
|---|---|
| `200` на `/` | публикация жива (корень) |
| `401` на `/hs/…` | сервис опубликован, ждёт Basic |
| `503` на `/hs/…` | сервис не опубликован или корень неизвестен |
| `404`/`405` | проба мимо `/hs/` — ничего не доказывает |

Первый запрос к сервису расширения после рестарта может висеть 10–20 с —
платформа грузит метаданные; таймауты ставить щедрые.

## Linux-грабли (все закрыты в publish_ib.sh)

1. **IPC-каталог** `/tmp/<user>.<uid>`: ibsrv создаёт его сам с правами 555
   и тут же не может bind-ить туда сокеты (`FATAL …channel.hpp:89,
   Error -13`). Лечение — предсоздать с 700 перед стартом; после ребута
   `/tmp` чист, повторять. Запуск всегда через `publish_ib.sh` — он делает
   сам.
2. **Root-прогон отравляет базу**: в каталоге ИБ появляются файлы чужого
   uid, дальше все запуски от обычного пользователя молча не открывают базу,
   клиенты получают «Ошибка открытия файла блокировок». Root-прогонов не
   делать; скрипт сторожит и громко отказывает с рецептом лечения.
3. **ibsrv на Linux живёт в distrobox-контейнере** (network=host, ipc=host —
   порты и `/tmp` общие с хостом), на хосте его не бывает; хостовая детекция
   doctor без контейнера даёт ложный WARN. Резолв: `1c.publish.ibsrv` /
   env `PUBLISH_IBSRV` = `distrobox:auto` (искать по живым контейнерам),
   `distrobox:<имя>` (гвоздь к одному) или готовая команда.
4. **SIGTERM ibsrv игнорирует** — гасить kill -9 по `lock.pid` из каталога
   данных; `publish_ib.sh stop` эскалирует сам.
5. **Зомби** (процесс жив, порта нет, в логе тихо) — чек-лист по частоте:
   владельцы файлов в каталоге базы → права `/tmp/<user>.<uid>` →
   `infobase.id` в конфиге (случайный UUID). `start` печатает его на
   таймауте.

## Канон контура

```bash
bash .zcode/1c/scripts/publish_ib.sh start   # → хвост E2E_PUBLISH_JSON {url, port, pid}
bash .zcode/1c/scripts/publish_ib.sh stop
```

`E2E_PUBLISH_JSON` парсят API-тесты (`PUBLISH_URL` — см. скилл
`1c-test-contour`, раздел API-контур). Живость вручную: `ss -tlnp | grep
<порт>` слушает `127.0.0.1`, curl корня отвечает 200.
