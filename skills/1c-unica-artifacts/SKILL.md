# Артефакты рантайма Unica: манифест, кэш, provider_unavailable

Итог живого рана (2026-10-09, unica 0.13.0-rc.7 после обновления плагина,
контур dealer): диагностика BSL отвечала `provider_unavailable`, пока
недостающий артефакт не перенесли в кэш плагина вручную — из кэша соседней
установки на той же машине. Разовый чек рассинхрона — `/1c-doctor`
(сверка манифеста с кэшем артефактов).

## Как Unica резолвит артефакты (0.13)

- Контракт — `runtime-manifest.json` в каталоге установленной версии
  плагина (`~/.zcode/cli/plugins/cache/<канал>/<плагин>/<версия>/`):
  `artifacts` → имя → `version` и `targets.<платформа>` → `asset.sha256` +
  `files[]` (относительный путь и sha256 каждого файла).
- Кэш —
  `~/.zcode/cli/plugins/data/<id-плагина>/runtimes/<имя>/<версия>--<sha256>/<платформа>/`;
  маркер завершённости — `.ready.json` (artifact, version, target,
  assetSha256). Суффикс каталога — ровно `asset.sha256` из манифеста.
- Резолв строгий по версии из манифеста: наблюдение рана — прежняя версия
  артефакта (0.2.67) при требуемой (0.2.86) означает «артефакта нет».
  Провайдер сам не докачивает, не откатывается и из чужих кэшей не берёт.
- Сервер при этом жив: handshake, tools/list, ping — всё зелёное. Провал
  всплывает только на первом вызове провайдера, поэтому после обновления
  юники его не видно до первой диагностики.

## Симптомы

- `bsl_diagnostics`/`bsl_index` в статусе вечно `stale`, файлов под ними
  не появляется.
- Вызов провайдера отвечает `provider_unavailable`, «BSL analysis did not
  complete, so the module is unproven».
- В логах демона: «bsl-analyzer is not bundled in this workspace» и
  «could not locate Unica plugin root for bsl-analyzer MCP adapter
  lookup».

## Диагноз по шагам

1. Версия установленной юники —
   `~/.zcode/cli/plugins/installed_plugins.json`, запись `unica`: поля
   `version` и `installPath`.
2. Что требует манифест — `<installPath>/runtime-manifest.json`:
   `artifacts.<имя>.version` и `targets.<платформа>.asset.sha256`.
3. Что лежит в кэше — `ls ~/.zcode/cli/plugins/data/<id>/runtimes/<имя>/`.
   Каталога `<версия>--<sha256>` нет — диагноз подтверждён.
4. `.partial/` в корне runtimes — след начавшейся и оборванной закачки; на
   закрытых стендах типичная причина — недоступность github releases
   (повторные попытки юники молча падают так же).

## Лечение: докачка или перенос из соседнего кэша

Артефакт требуемой версии часто уже на машине — в кэше другой установки
юники (`~/.codex/unica/runtimes`, второй канал, omp-наследие). Перенос
легален после байт-сверки с манифестом:

```bash
VER=0.2.86                        # version из манифеста
SHA=<asset.sha256 целиком>        # из targets своей платформы (напр. linux-x64)
SRC="$HOME/.codex/unica/runtimes/bsl-analyzer/${VER}--${SHA}"
sha256sum "$SRC/linux-x64/bsl-analyzer"   # совпасть с манифестом байт-в-байт
cp -r "$SRC" "$HOME/.zcode/cli/plugins/data/unica@unica-next/runtimes/bsl-analyzer/"
test -x "$HOME/.zcode/cli/plugins/data/unica@unica-next/runtimes/bsl-analyzer/${VER}--${SHA}/linux-x64/bsl-analyzer"
```

`.ready.json` приезжает вместе с каталогом; его поля обязаны совпадать с
манифестом — по ним unica признаёт артефакт завершённым. Рестарт сервера
не нужен: резолв происходит на очередной вызов провайдера. Старые версии в
кэше не мешают — не трогать. Повторная закачка (перезапуск сессии на
машине с доступной сетью) — равноправный путь: появившийся каталог сверить
с манифестом тем же `sha256sum`.

## Грабли

- Пустой ответ провайдера ≠ «чисто»: `provider_unavailable` значит «анализ
  не выполнялся» (дух скилла `unica:code-diagnostics` — чистый ответ и
  неотработавший провайдер различимы). Не переписывай код по находкам,
  которых не было.
- `.partial` может остаться и после починки остальных артефактов — сам по
  себе не мешает (пересоздаётся при каждой неуспешной закачке), но это
  маркер того, что закачка на машине не работает: рассчитывай на перенос
  из соседнего кэша.
- После копии проверить `test -x` (и для unpack-артефактов — целостность
  файлов по `files[]` манифеста): без исполняемого бита провайдер падает
  уже на запуске бинаря.
- Артефакт-версии меняются вместе с плагином: после каждого Update unica
  рассинхрон ожидаем. `/1c-doctor` назовёт недостающий артефакт и версию
  до первого `provider_unavailable`.
