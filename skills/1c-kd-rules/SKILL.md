# Правила обмена через MCP 1c-kd (kd-rules-mcp)

Сервер — вендор-копия [egordoronchenko/kd-rules-mcp](https://github.com/egordoronchenko/kd-rules-mcp)
(MIT, пин и процедура синка — `vendor/kd-rules-mcp/UPSTREAM.md` контура). Транспорт — streamable
HTTP на петлевом интерфейсе; в проекте сервер объявляет `wire_config.py` под именем **`1c-kd`**,
URL берётся из `.zcode/1c/contour.json` → `1c_kd.url` (умолчание `http://127.0.0.1:8060/mcp`).
Что во что конвертировать, решает агент; сервер детерминированный — разбирает выгрузки,
предлагает кандидатов, пишет XML и проверяет. Содержательные каноны работы — скиллы
`kd2-rules-build`, `kd2-exchange-pitfalls`, `kd3-rules`; полный список инструментов с
сигнатурами — `vendor/kd-rules-mcp/docs/tools.md` (в репо контура).

## Установка и старт (один раз на машину)

```bash
scripts/install_kd_rules.sh    # станция ~/.local/share/1c-zcode/kd-rules-mcp, uv sync (первый раз — минуты)
scripts/start_kd_rules.sh      # поднять сервер; --status / --stop / --print-config; лог <станция>/kd-rules.log
```

Первый старт создаёт `projects.yaml` из примера — заполни его. Перезапусти сессию ZCode, чтобы
`1c-kd` подключился; проверка цепочки: `project_list`, затем `structure_load_project` (число
объектов конфигурации; первая загрузка большой выгрузки — до пары минут, дальше из кэша).

## Конфигурация проектов

- `projects.yaml` станции — описания 1С-проектов: XML-выгрузки конфигураций и расширений
  (формат Конфигуратора, не EDT), базы-песочницы, `rules_dir`, обмены. Общий файл — можно
  передавать коллегам, путей машины в нём нет.
- `projects.local.yaml` рядом — машинные абсолютные пути (`projects:`), порт/`bind`/`token`
  при нужде; **в git не попадает** (по канону контура — местный слой).
- Сервер пишет только в рабочую папку станции (`workspace/`) и в `rules_dir` проекта с
  флагом `writable` — остальное read-only.

## Обновление

`scripts/install_kd_rules.sh` пересинхронизирует код станции (состояние — projects, workspace,
cache — не трогает), затем `start_kd_rules.sh --stop` и старт заново. Новый апстрим — по
процедуре `UPSTREAM.md` (замена вендор-копии, forbidden-names, тесты, пин).

## Границы канала

- Пакет MCP-серверов comol (vibecoding1c: граф кода, синтакс-чекер, БСП-поиск) в поставку
  **не входит**: код обработчиков агент пишет через unica (`mcp__unica__*`), синтаксис —
  проверка BSL-каналами контура.
- `kd_check`/`bsp_check` (штатная загрузка правил в базу КД/БСП) — опциональные проверки
  Windows-машины с платформой; в контур не ставятся, сервер работает без них.
- `rules_dir`/`writable_extensions` дают серверу запись в проект — подключай осознанно,
  прод-выгрузки держите вне записи.
