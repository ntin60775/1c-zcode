## G1 — миграция omp → zcode: нет живого прогона

- **Что есть:** `scripts/migrate_from_omp.py`, команда `/1c-migrate-from-omp`,
  `docs/MIGRATION-FROM-OMP.md` (критерий чистоты: grep `\.omp` и др. = 0
  находок вне git-истории).
- **Чего нет:** подтверждённого прогона на реальном omp-проекте; все
  предыдущие проверки — на пилоте, который контуром не мигрировался, а
  вендорился с нуля.
- **Устранение:** прогнать мигратор на первом omp-проекте парка (+ ворктри
  тем же скриптом), довести до зелёного `/1c-doctor`; потом остальные
  проекты пакетно. Юзер-слой — отдельно, вручную с подтверждением.
- **Критерий закрытия:** первый проект парка прошёл §5–7 плана: дерево без
  omp-остатков, `/1c-doctor` зелёный, живые гейты сработали хотя бы раз.

## G2 — конвертация старого покрытия: доказана на одной фиче

- **Что есть:** канон в skills/1c-test-contour (фича = источник → один
  `test_<имя>.py` write-first → зелёный → `git rm` фичи; инварианты yAxUnit →
  логика-тесты onec_db, пользовательские пути → GUI-e2e); workflow
  `1c-e2e-author`; живой кейс уровня D пилота (1 фича, конвертирована и
  удалена после зелёного прогона).
- **Чего нет:** доказательства масштабирования на весь объём старого
  покрытия парка.
- **Устранение:** конвертировать покрытие первого omp-проекта парка пакетно
  по канону выше; каждую фичу — до зелёного прогона, инварианты не
  выбрасывать.
- **Критерий закрытия:** в архиве `docs/omp-migrated/tests/` не осталось
  непокрытых фич; каждая либо конвертирована, либо осознанно помечена
  legacy с обоснованием.

## G3 — bsl_style_gate: блокировка не проверена живым срабатыванием

- **Что есть:** HARD_BLOCK=True, фильтр изменённых строк, тесты 13/13,
  вендоринг на пилот (f56e52e03).
- **Чего нет:** живого прогона «правка с нарушением → exit 2 + причина в
  stderr» внутри сессии агента.
- **Устранение:** на пилоте сделать пробную правку `*.bsl` с заведомым
  нарушением, зафиксировать блокировку и текст причины; повторить сценарий
  в живой фиче.
- **Критерий закрытия:** зафиксированное живое срабатывание (exit 2) и
  разблокировка после исправления.

## G4 — 9 операций тест-клиента работают через обходы

- **Что есть:** issues #1–9 (read_rows на динамическом списке, cancel_edit,
  goto_date, is_visible/click, get_command_interface, get_user_message_texts,
  find_rows-условия, get_screenshot в distrobox, readback флажка) — все с
  обходами, канонизированными в реестре skills/1c-testpilot.
- **Чего нет:** апстримных фиксов testpilot; обходы — постоянная практика,
  а не временное решение.
- **Устранение:** держать issues открытыми, при обновлении testpilot
  перепроверять (процедура — cron-автоматизация проверки обновлений);
  закрывать issue после живой перепроверки фикса.
- **Критерий закрытия:** все 9 issues закрыты с живой перепроверкой на
  актуальной версии testpilot.

## Примечание: топология установки (не отклонение)

Плагин вендорит skills/hooks/workflows/scripts/templates в `.zcode/`
проекта, bootstrap пишет секцию AGENTS.md, `wire_config.py` подключает MCP
и хуки. Внешние зависимости ставятся не одним пакетом, а по топологии:
`1c-testpilot` — `scripts/install_testpilot.sh` (пин ==1.8.1), паки
`1c-bsl-code-style` и `1c-ssl-skills` — записями каталога
sot-zcode-marketplace. Наличие и живость всего набора проверяет
`/1c-doctor`. Это осознанная топология поставки, а не пробел.
