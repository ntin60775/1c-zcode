# Миграция со старого omp-контура на 1c-zcode

Старый контур (omp/1c-omp 0.1.x + unica 0.12.3 + ontoship-omp) живёт в
проектах в `.omp/`; новый — вендорен в `.zcode/`. Миграция **атомарна на
проект**: в одном дереве не работают оба контура одновременно (двойные
гейты, двойная путаница). Ворктри мигрируются тем же скриптом по каждому
дереву.

Исполнитель: `scripts/migrate_from_omp.py <корень> [--apply]` (по умолчанию
dry-run) или команда `/1c-migrate-from-omp`. Git-коммиты делает агент,
не скрипт.

## Что переносится и что удаляется

| Артефакт старого | Судьба |
|---|---|
| `.omp/unica-gate-escalations.txt` | → `.zcode/unica-gate-escalations.txt` (формат сохранён) |
| `~/.omp/logs/rule-audit.jsonl` | → `<проект>/docs/ops/gate-audit-archive.jsonl` (аудит-след решений гейтов) |
| `.omp/rules/*.md`, `.omp/RULES.md`, `.omp/APPEND_SYSTEM.md` | смысловое — в секцию AGENTS.md контура (маркеры BEGIN/END 1C CONTOUR); файлы удаляются |
| `.omp/extensions/docs-gate.ts` (строгий проектный) | его логика — канон плагинного `doc_gate.py`; после сверки удаляется |
| `.omp/` целиком (включая `plugins/`, backup) | удаляется (tracked — `git rm`) |
| omp-блок в `.gitignore` | вычищается |
| `tasks/init-worktree.sh` | перепривязывается на `.zcode/1c/scripts/init_worktree.sh` |
| `v8project.yaml` / `v8project.local.yaml` | **остаётся** (внешний контракт v8-runner/unica) |
| `tools/VAParams*`, `tools/yaxunit.json`, `tasks/mcp/`, `features/` | legacy: не удаляются; Vanessa-стек выведен из контура, `features/` убираются после покрытия testpilot-сценариями |
| AGENTS.md проекта | из него убираются omp-упоминания; KB-секция (ontoship, `.gitmark`) не трогается — владелец другой |

## Критерий чистоты

После применения скрипт greps-ит проект: упоминаний `\.omp`, `omp plugin`,
`unica-gate.ts`, `~/.omp` вне git-истории быть не должно. Остаточные
находки печатаются списком — дочистка руками/агентом.

## Порядок по парку проектов

1. **Пилот**: основной проект + его ворктри (один из них без контура —
   контрольный образец). Отладить процедуру, прогнать живые гейты и
   testpilot-стенд, снять фактические `mcp__unica__*` имена.
2. Остальные проекты (ut-10, retail, zupupr, erp-demo, erp-mini,
   project-bp) — тем же скриптом. Дрейф версий 1c-omp (0.1.5/0.1.7/0.1.8)
   между деревьями нормализуется сам: новый контур один.
3. **Юзер-слой — в конце, вручную с подтверждением** (после того, как все
   проекты переехали и новый контур подтверждён в бою):
   - архив `rule-audit.jsonl` уже в проектах; остаток `~/.omp/` (~3.7 ГБ) — удалить;
   - `~/.codex/unica/runtimes/0.12.3` (382 МБ) — удалить (ZCode-канал качает
     рантаймы в своё plugin-data);
   - бинарь `~/.bun/bin/omp` — удалить последним.
   Это mass-deletion за пределами порогов: выполнять по явному подтверждению.

## Откат

До git-коммита: `git checkout -- .` в проекте возвращает всё, кроме
gitignored-остатков `.omp/plugins/` (симлинки в общий кэш `~/.omp/plugins` —
пересоздаются `omp plugin install`). После коммита — git-история.
