# Канон текстов контура: скиллы, правила, сообщения гейтов

Тексты контура — рабочие инструкции агенту и оператору, не документация
«вообще». Правило описывает, как делать правильно сейчас; история живёт
в git-коммитах и трекере. Канон обязателен для скиллов (`skills/`), секций
правил (AGENTS.md, `templates/agents-section.md`), сообщений гейтов
(stderr при блокировке) и доков `docs/`.

## Смысловое направление

1. **Знание, не история.** Текст — текущая правда. Хроника («живые пробы»,
   «наблюдение такого-то числа», «раньше работало»), даты канонов и
   атрибуции, имена сессий — не пишутся.
2. **Happy path.** Текст описывает штатный путь; обходы — только когда они
   часть пути (эскалации, ритуал первой базы). История расследования,
   приведшего к рецепту, в текст не входит.
3. **Класс, не частный случай.** Правило формулируется для класса явлений
   («любая похожая ошибка загрузки»); ограничение привязывается к носителю
   («вторая сессия на одной и той же базе»), не к типу и не к машине.
4. **Проектных фактов нет.** Порты, имена баз, учётки, пути, дисплеи —
   только из конфигов с именем ключа (`contour.json → 1c_db.url`), без
   литералов. Механизм контроля — `.forbidden-names.txt`.
5. **Границы честно, без дат.** «Не проверено» и «Граница проверенности» —
   граница применимости канона: остаются. Указатели на живые ограничения
   апстрима (#939, #1246, unica#937) — адреса явлений: живут, пока живо
   ограничение.
6. **Дисциплина ресурсов.** Правило уборки живёт рядом с правилом
   создания: поднял техжурнал — в том же разделе правило «убрать за
   собой»; черновые каталоги проб — снести после разбора.
7. **Механизм важнее симптома.** Фиксируется «почему» (механизм платформы,
   раннера, гейта), не только «что сделать».

## Структура

- Frontmatter: `name`, `description` (≤ 1024 символа, триггерные слова —
  в первых ~250), `when_to_use` — честный; `license`/`metadata` — по
  необходимости. Проверка — `scripts/lint_skill_frontmatter.py`.
- Жанровые секции: «Порядок» (шаги), «Грабли» (повторяемые ловушки —
  знание, не история), «Граница проверенности», «Канон контура» (команды),
  «Смежное» (маршрутизация на соседние навыки).
- Реестры — таблицами, команды — код-блоками. Каждый путь/скрипт/файл,
  на который ссылается текст, существует — проверяется при правке.
- Один навык — одна зона ответственности; канон не дублируется между
  навыками (дубль = будущий рассинхрон) — ссылайся на навык-хозяин.

## Язык и типографика

- Регистр: инструкции агенту — императив ед. ч. («проверь», «гаси») или
  инфинитив; «вы»-формы не используются.
- Активный залог, действующее лицо явное; инверсии «кто кого» — дефект:
  «`wire_config.py` объявляет сервер», не «сервер объявляет
  `wire_config.py`».
- Конкретика с числами, не оценки («до трёх минут», не «быстро»).
  Телеграфный рецепт в списках — норма жанра («сделал X → проверил Y»).
- Тире — 1–2 на абзац, параллельный ряд считается одним; перед «это»
  в связке — тире. Кавычки «ёлочки», вложенные — „лапки“; диапазоны —
  через –; многоточие — ….
- Сокращения с пробелом: «т. д.», «т. п.», «т. е.»; слитные «т.д.» —
  дефект.
- Невидимых символов (NBSP) нет — конвенция grep-гигиены репо, осознанное
  отступление от карточки ru-text.
- Термины контура (прогон, стенд, гейт, пин, дифф, ретрай) — норма;
  англицизм вместо точного русского слова («интеракция» вместо
  «взаимодействие») — дефект.
- Машинные слои языковыми проходами не трогаются: таблицы, код-блоки,
  команды, пути, YAML-обвязка frontmatter (текст `description` правится,
  кавычки-делимитеры — нет). Цитаты чужих текстов (сообщения платформы) —
  as-is.
- Ширина строки: 1c-группа ≤ 80; kd-группа — ширина апстрима (минимальный
  diff при синке).

## Процесс

- Новый навык: frontmatter по линту → forbidden-names → все пути из текста
  существуют → коммит.
- kd2-*/kd3-* — вендор-слой: правки только в переносимом слое (frontmatter
  и точечные замены), канон синка — `vendor/*/UPSTREAM.md`; авторская
  правка там, где синк её снесёт, не делается.
- Правка канона: 2–3 прохода; каждый — против первоисточников (код,
  конфиги, живые ответы), не самосогласованности. Формальные грепы
  обязательны: даты, «наблюдение/было/стало», слитные сокращения, имена
  проектов. «Финально» — только после прохода без находок; приёмка за
  владельцем.
- Сообщения гейтов: причина + рецепт лечения, той же типографикой, по
  одной строке на нарушение.

## Примеры правок (дефект → норма)

| Дефект | Было | Стало |
|---|---|---|
| падеж в перечислении | «…workflows, журнала deploy» | «…workflows, журнал deploy» |
| инверсия «кто кого» | «сервер объявляет wire_config.py» | «wire_config.py объявляет сервер» |
| англицизм | «интеракция пользователя» | «взаимодействие пользователя» |
| плеоназм приблизительности | «до ~3 минут» | «до трёх минут» |
| регистр | «откройте… и оформите» | «открыть… и оформить» |
| слитное сокращение | «и т.д.» | «и т. д.» |
| пропуск тире | «выбор структуры это решение» | «выбор структуры — это решение» |
| хроника с атрибуцией | «(решение владельца, дата)» | (правило без атрибуции и даты) |
