## Контур 1С (1c-zcode)

Владелец секции — плагин 1c-zcode; правится контуром, не руками.
Версия секции следует за тегом контура в `.zcode/deployed.json`.

### Инварианты

1. Исходники 1С (`src/{cf,cfe,epf,erf}`, `tests/{cfe,epf}`) правятся
   только через Unica MCP — прямая правка блокируется гейтом.
   Разовый обход: `.zcode/unica-gate-escalations.txt`.
2. Расширения собираются только с `fullRebuild: true`; основная
   конфигурация — только инкрементально. Нарушение блокируется.
3. Мутация метаданных/кода — после сверки с документацией платформы
   (`unica.documentation.*` / `unica.standards.*`, непустой результат).
4. Адрес инфобазы и креды — только из `v8project.local.yaml`.
5. Прод-контур по умолчанию (fail-closed): изменяющие инструменты
   тест-контура блокируются; признак `test` — ключ `contour:` в
   `v8project.local.yaml` или `.zcode/contour`.
6. Третий идентичный повтор упавшей команды заблокирован.

### Качество кода

Форма BSL — пак `1c-bsl-code-style` (приоритет над стандартами и
стат-анализом). Вызовы БСП — скилл `bsp` (БСП 3.1.11). Обзор — скилл
`1c-contour` (маршрутизация файл → инструмент, приоритеты качества).

### Тесты и данные

Поведение проверяется e2e-сценариями 1c-testpilot (record-first, readback,
ЖР-сверка; workflows `1c-e2e-run` / `1c-e2e-record`), данные — MCP `1c-db`.
Юнит-тесты, написанные агентом, не поддерживаются.
